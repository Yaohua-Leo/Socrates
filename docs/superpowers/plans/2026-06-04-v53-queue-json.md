# v0.53 Queue JSON Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development before implementation. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `queue --json` so wrappers, UI prototypes, plugins, and automation can consume the full deterministic learning queue without parsing Markdown.

**Architecture:** Build a structured read-only queue payload from the same queue collectors used by Markdown output. JSON mode must preserve section filtering and must not generate briefs, refresh reports, run repairs, call an LLM, score learning, approve artifacts, or mutate project state.

**Tech Stack:** Python argparse, existing learning queue readers, shared project-title helper, `json`, `unittest`, deterministic temporary project fixtures.

## Acceptance Criteria

- `python -m socrates queue --project <project> --json` exits 0 and emits valid deterministic JSON.
- The payload includes `schema_version: 1`, `quality_boundary: deterministic_learning_queue`, `project`, `root`, `section`, `action_summary`, and `sections`.
- `action_summary` exposes completion, open-action, blocker, continue-learning, human-review, and next-action fields without parsing Markdown.
- `sections` preserves deterministic queue ordering and exposes `section`, `title`, `count`, and structured `items` rows with `item_id`, `path`, and `detail`.
- `--section <name> --json` filters `sections` to the selected section; `--section summary --json` returns only the action summary with no section rows.
- Markdown queue output remains stable.
- JSON mode is read-only and does not write project logs, reports, briefs, learning state, queue artifacts, or any project file.
